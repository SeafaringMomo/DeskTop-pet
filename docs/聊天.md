# 聊天模块

桌面助手与用户的对话入口，含聊天窗口、历史对话窗口、对话记录持久化、AI 编排与 TTS 朗读。

## 涉及文件

| 文件 | 作用 |
|---|---|
| `Windows/Talk/TalkWindow.xaml(.cs)` | 聊天主窗口（输入、输出、模型按钮、历史按钮、麦克风） |
| `Windows/Chat/ChatHistoryWindow.xaml(.cs)` | 历史对话窗口（会话列表 + 消息内容） |
| `Services/AI/ChatOrchestrator.cs` | 多轮对话 + 工具调用编排器 |
| `Services/AI/AiProviderRegistry.cs` | AI 提供方注册表（单例） |
| `Services/AI/IAiProvider.cs` | 通用 AI 接口 + 请求/响应/工具类型 |
| `Services/AI/Providers/LocalKleeProvider.cs` | 本地占位实现（离线兜底） |
| `Services/AI/Providers/OpenAiCompatibleProvider.cs` | OpenAI 兼容 HTTP 适配器 |
| `Services/Data/ChatHistoryRepository.cs` | 对话记录 SQLite 仓储 |
| `Services/Core/TTSService.cs` | System.Speech 文本转语音 |
| `Services/Core/SpeechRecognitionService.cs` | 麦克风语音识别（听写） |
| `Models/ChatMessage.cs` | 对话记录模型（ChatSession + ChatMessageRecord） |

## 聊天窗口（TalkWindow）

**配色随角色切换**（默认角色=草帽黄/红/棕；索隆=绿/棕等），由 `ApplyTheme(role)` 应用：标题栏为「主色 → 强调色」水平渐变，外框为主色边框，输入/输出区为表面色背景。

### 标题栏按钮

- **⚙ 模型**：打开模型设置窗口（详见 [config配置.md](config配置.md) 的 secrets.yaml 部分）
- **📜 历史**：打开历史对话窗口
- **✕**：隐藏聊天窗（不销毁，便于反复打开）

### 输入区

含输入框 + **🎤 麦克风按钮**（语音输入）：
- 点击 🎤 开始麦克风识别（按钮变为 🔴 强调色高亮），系统录音并实时识别
- 再次点击停止，识别到的文本自动追加到输入框
- 基于 `SpeechRecognitionService`（System.Speech.Recognition），优先中文（zh-CN）识别引擎，系统未安装中文语言包时回退到默认引擎
- 识别失败会在输出区提示（如 Windows 未启用语音识别功能）

### 发送流程

输入回车后：
1. `InputBox_KeyDown` 把文本追加到输出区（`你：xxx`）
2. `PersistMessage("user", text)` 持久化用户消息到 `chat_history.db`
3. **P9 好感度联动**：`AffinityService.AddAffinity(role, +1, applySatietyBonus: true)`——聊天每条消息 +1 好感度，饱食度>80 时 ×1.2 加成
4. `Task.Run(() => ProcessAsync(text))` 后台线程发起请求
5. AI 回复后追加到输出区（`默认角色：xxx`）并 `PersistMessage("assistant", reply)`
6. `TTSService.Speak(reply)` 朗读回复（同步，在后台线程）

主角称呼（"默认角色："）取自配置文件，切换角色后称呼也跟着变。

### 流式分支（python-agent）

若当前提供方实现 `IStreamingAiProvider`，`ProcessAsync` 改走 `ProcessStreamAsync`：

| 事件 | 界面行为 |
|---|---|
| `chunk` | 追加到回复气泡（逐字显示） |
| `step_start` / `step_finish` | 状态行显示「思考中（第 N 轮）」 |
| `tool_start` | 状态行显示「正在调用工具：todo_add」 |
| `tool_finish` | 状态行显示结果摘要（失败标红） |
| `done` | 记录最终文本；流结束后统一落库 + TTS 朗读**一次**（chunk 阶段不朗读） |
| `error` | 状态行显示错误，回复气泡追加错误提示，不落库 |

其他要点：
- 会话 ID 在首次发送时创建；`_sessionId == 0` 时 `PersistMessage` 会自动建会话
- 从历史窗口「加载」会话时会调用 `ChatOrchestrator.LoadHistory(...)` 重建上下文
- 关闭窗口或重新发送时取消上一个 `_streamCts`，避免流式任务泄漏
- 工具执行由 Python 负责，C# 不注入 MCP 工具（避免重复执行）


## 历史对话窗口（ChatHistoryWindow）

从聊天窗口标题栏「📜 历史」按钮打开。功能：
- 左侧会话列表：显示当前用户所有历史会话（标题 + 时间），按更新时间降序
- 右侧消息内容：选中会话后显示该会话的所有消息（用户/助手/工具）
- **加载到聊天窗**：点「加载」按钮把选中会话的历史消息灌入 `ChatOrchestrator.History`，继续对话
- **删除会话**：点「删除」移除选中会话
- 时间显示用 `Mode=OneWay` 绑定（避免只读属性 `DisplayTime` 触发 TwoWay 探测异常）

## 对话记录数据库（chat_history.db）

基于 SQLite 的对话记录仓储，**按用户隔离**（`user_data/users/<name>/chat_history.db`）。

### 表结构

#### ChatSession（会话）

| 字段 | 类型 | 说明 |
|---|---|---|
| `Id` | INTEGER PK | 会话 ID（自增） |
| `Title` | TEXT | 会话标题（首条消息前 20 字，初始为"新对话"） |
| `Role` | TEXT | 当时对话的角色名（如 `默认角色`） |
| `Provider` | TEXT | 当时使用的 AI 提供方名 |
| `CreatedAt` | TEXT | 创建时间（ISO 8601） |
| `UpdatedAt` | TEXT | 最后更新时间（ISO 8601） |

#### ChatMessage（消息）

| 字段 | 类型 | 说明 |
|---|---|---|
| `Id` | INTEGER PK | 消息 ID（自增） |
| `SessionId` | INTEGER FK | 所属会话 ID（索引 `idx_chatmsg_session`） |
| `Role` | TEXT | `user` / `assistant` / `tool` |
| `Content` | TEXT | 消息内容 |
| `Timestamp` | TEXT | 时间戳（ISO 8601） |
| `ToolCalls` | TEXT | 工具调用附带的元信息（可空） |

### ChatHistoryRepository 方法

| 方法 | 用途 |
|---|---|
| `CreateSession(role, provider)` | 新建会话，返回会话 ID |
| `AddMessage(sessionId, role, content, toolCalls?)` | 追加一条消息；若会话标题为"新对话"则更新为首条消息前 20 字 |
| `ListSessions()` | 列出所有会话（按 UpdatedAt 降序） |
| `GetMessages(sessionId)` | 获取指定会话的所有消息（按时间升序） |
| `DeleteSession(sessionId)` | 删除会话及其所有消息 |
| `ClearAll()` | 清空当前用户的所有会话 |

### 自动标题

首次 `AddMessage` 写入用户消息时，若会话标题仍为"新对话"，则自动更新为该消息内容前 20 个字符。

## 聊天编排器（ChatOrchestrator）

在 `IAiProvider` 与 `McpManager` 之间执行多轮对话 + 工具调用循环：

```
用户消息
  ↓
ChatOrchestrator.TalkAsync
  ↓
AiProviderRegistry.Default (IAiProvider)
  ├─ LocalKleeProvider (本地占位，无工具调用)
  ├─ OpenAiCompatibleProvider (HTTP, 支持工具调用)
  │    ↓ 模型请求工具调用
  │    McpManager.InvokeToolAsync
  │    └─ LocalTodoMcpServer (todo_list/add/complete/delete)
  │    ↓ 工具结果回传模型
  │    模型继续生成
  └─ PythonAgentProvider (流式，工具循环在 Python 内完成)
       ↓ POST /v1/chat/stream（SSE 逐事件返回）
       Python AgentLoop
       ├─ LLM 流式输出
       └─ 工具调用
            ├─ memory_* / web_* / exec_run（Python 本地执行）
            └─ todo_* → 工具桥 → McpManager → LocalTodoMcpServer
  ↓
最终回复 + TTS 朗读
```

### 关键属性

- `MaxToolRounds`：单次会话允许的最大工具调用轮数（默认 6），防止死循环
- `SystemPrompt`：系统提示（角色设定），由 `BuildDefaultSystemPrompt()` 动态生成
  - 读取 `ConfigService.Load().Role` 获取当前角色名
  - 调用 `AffinityService.GetSystemPromptHint(role)` 注入好感度等级提示（影响 AI 对话风格）
  - 切换角色或好感度变化后，下次新建 `ChatOrchestrator` 时生效

### 兜底回复

达到 `MaxToolRounds` 仍未结束时返回：「（处理了好多步还是没搞明白…能换个说法再问一次吗？）」

## 好感度联动（P9）

聊天与好感度系统联动：
- **每发送一条消息 +1 好感度**（`Rewards.ChatPerMessage`，默认 1）
- 饱食度>80 时 ×1.2 加成（`Rewards.SatietyHighBonus`，默认 1.2）
- 好感度等级影响 AI 对话风格：通过 `ChatOrchestrator.BuildDefaultSystemPrompt()` 注入系统提示
  - 挚友（80+）：可非常亲密地称呼对方
  - 亲密（60+）：可以亲近地交流
  - 友好（40+）：可以主动关心对方
  - 认识（20+）：偶尔可以热情一些
  - 陌生人（0+）：保持礼貌的距离感

详见 [助手管理数据库.md](助手管理数据库.md) 的好感度部分。

## 已知限制

- **OpenAI 工具调用多轮对话**：`ChatOrchestrator` 在历史消息中只保存了文本内容，未携带 OpenAI 协议要求的 `tool_calls` 结构化字段和 `tool_call_id`。单轮工具调用可正常工作，连续多轮工具调用的第二次请求可能被部分严格的 OpenAI 兼容服务拒绝。走 `python-agent` 时不受此限制。
- **TTS 音色**：依赖 Windows 已安装的中文语音包；未安装时使用系统默认语音。
- **流式内容不落库中间的 chunk**：只保存 `done` 的最终文本；若流中断（网络/取消），该轮回复不入库。
- **流式与好感度**：好感度在发送时 +1（与是否成功无关），失败不退还。
